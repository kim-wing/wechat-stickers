# 连续帧优先更新 · 2026-09-10

> 后续更新：原生透明 PNG 已成为默认，视频备选及其脚本、命令、配置和专用说明已删除。以下为历史更新记录，视频相关内容不再适用于当前版本。

动态表情默认改为「图像模型生成连续帧 → 切帧 → GIF」，Seedance 视频保留为可选路线。此次更新同时修改 Skill 指令、提示词参考、执行脚本和测试，不只是替换模型名称。

## 为什么这样改

表情的目标是表达一个清楚的聊天反应。生成方式服务于角色一致性、动作可读性、循环衔接和最终文件质量。旧版因连续帧不稳定而默认视频，并积累了强制视频、连续帧额外批准等限制；这些历史选择不应成为永久要求。

新版把发送情境、动作设计和生成方式分开。先定义不变元素及动作阶段，再用小规模实测选择路线。模型升级是尝试连续帧的理由，不是跳过验收的理由。

## 主要变化

- 新建动态任务默认 `animated_source_mode: sprite_sheet`。沿用兼容字段名，含义为图像生成的时序帧表，不需要 Ark Key。
- 新增 `process-sheets`：原图检查、候选来源记录、GIF 编码及状态保存。实际出图仍由图像工具完成。
- 提示词按角色、单一动作、帧序、阶段、不变元素、背景和边距组织。
- 对单张 GIF 测试按需读取文档，避免加载整套专辑与视频流程。
- 按比例取整切帧，接受不能被行列数整除的实际图片尺寸，原图保持不变。
- 空帧被明确拒绝，修复空白帧表因变化量为零而误判稳定的问题。
- 检查摘要增加绝对变化量和可疑相邻帧编号，包含首尾帧，便于定点检查。
- 子命令完整日志留在 `reports/`，终端返回简要结果；预期子命令失败保留非零退出码，不再输出整段 Python 堆栈。
- `package` 在打包前重新运行标准 QC；单张表情的 QC 正确使用 `single`，不强制专辑素材。
- 保留现有质量阈值、来源审计和失败报告，不通过降低验收标准节省 token。

## 两次真实生成测试

两次均使用内置图像生成工具。工具未提供可核验的底层模型标识，因此不将这些结果归为某一具体模型版本的性能证明。

| 测试 | 生成过程 | GIF | 检查结果 |
| --- | --- | --- | --- |
| 小猫钓鱼 | 首次生成后进行一次定点修改 | 240×240，16 帧，226,523 字节 | 第二版角色位置/尺寸更稳定，但最终动作差异和循环差异两项未通过；仅作为测试预览 |
| 参考角色上班打字 | 一次生成，以用户参考图约束角色身份 | 240×240，16 帧，207,771 字节 | 82 项技术检查全部通过；解码抽帧检查了浅色/深色背景上的边缘和角色细节 |

小猫案例说明，静止阶段多时，相对差异指标可能被较小的基准放大，但不能据此自动认定误报。首尾仍可能出现实际变化，必须查看对应帧并检查播放效果。

上班案例验证了参考角色与局部动作的可行性，不代表复杂全身动作同样稳定。此次可记录的人工视觉检查为解码抽帧检查；不把接触表当作完整播放验收，也不把技术通过等同于微信平台审核通过。

## 使用方式

从 Skill 目录运行：

```bash
python3 scripts/run_wechat_sticker_pipeline.py init \
  --output-dir /absolute/job --pack-name "工作中" --count 1 --motion animated
```

填写 `sticker-plan.json` 中的动作与来源字段：`sheet_source_path`、`candidate_id`、`rows`、`cols`、`frame_duration_ms`、`visual_review`。先检查原图，再如实记录 `raw_sheet_ok` 与具体观察。

```bash
python3 scripts/run_wechat_sticker_pipeline.py process-sheets --plan /absolute/job/sticker-plan.json
python3 scripts/run_wechat_sticker_pipeline.py qc --plan /absolute/job/sticker-plan.json
```

完成实际播放检查后可运行 `package`。完整流程和提示词见 [连续帧说明](../references/sequential-frames.md)。

## 兼容与限制

- 已有视频项目不自动切换路线。新视频任务显式设置 `--animated-source-mode green_screen_video` 或 `background_video`，仍需对应服务凭据。
- 目前支持等分帧表，不支持任意独立图片目录直接作为连续帧输入。
- 默认检查仍要求至少 12 帧。这是保守的本地预设，不是平台规定或帧数越多越好的证明。
- 出图工具可能不遵守指定分辨率、精确姿态或网格布局，需检查实际输出。
- 节省来自少读重复内容、压缩日志及定点诊断；尚未测量 token 节省比例。
- 不包含本地参考图片、私人路径、任务日志或生成素材；本次发布内容为 Skill、脚本、测试及文档。

## 验证

```bash
python3 -m unittest discover -s tests -v
```

6 项离线回归测试涵盖默认路线无视频依赖、空帧拒绝、成功编码、模式锁、失败阻止打包、可疑帧排序及非整除网格切分。合成测试图片仅验证处理逻辑，不作为生成质量证据。
