# 原生透明 PNG 与完整专辑交付更新

本次更新只保留静态 PNG 与图像连续帧 GIF，默认保留原生透明通道，并修复整套专辑漏生成赞赏配图的问题。

## 原生透明 PNG 优先

生成静态表情、动画帧表、封面和图标时，优先请求真实透明背景。处理器读取实际 alpha：已有透明度时保留颜色和透明度，不再去除洋红色；不透明旧素材保留原有去色兼容。另移除了帧表切分前后重复去色。

原生透明减少了背景色约束、去色修复和重试机会，但尚未量化 token 节省。切帧、统一缩放、GIF 编码、角色一致性和首尾循环检查仍然必需。PNG 的半透明边缘转换成 GIF 的二值透明时可能发生变化，因此不能跳过最终边缘检查。

少量透明像素不代表整张图背景合格；仍需检查是否存在伪透明棋盘格或残留背景。现有色边启发式可能标记角色自身的洋红色，遇到时应检查原图，不应直接删除角色颜色。

## 移除视频备选

删除 Seedance 生成、视频转 GIF 脚本及其专用文档、命令和配置。动态模式只接受 `sprite_sheet`，不再依赖视频服务密钥。

这是旧视频任务的兼容性变化：历史任务需使用仓库旧版本继续维护，或重新生成有来源记录的连续帧。不得仅修改来源字段来把旧视频伪装成图像生成结果。此次没有修改用户的历史任务目录。

## 修复专辑赞赏图遗漏

此前精简 Skill 时，将“专辑默认生成赞赏图”改成了“按要求生成”。真实专辑任务因此只规划封面、图标、横幅；后续 QC 虽然报告缺失，但发现得太晚。

现在默认专辑交付包括：

- 主表情和缩略图
- 封面 `cover`
- 图标 `icon`
- 横幅 `banner`
- 赞赏引导图 `reward-guide`
- 赞赏感谢图 `reward-thanks`
- 元数据、预览和质量报告

两张赞赏图无需用户另外提醒。计划校验会检查全部配套素材条目，提前拦截漏项；条目存在不等于图片已生成，最终 QC 仍检查实际文件。预览必须说明待完成或失败项，不能取消后续交付工作。

只有用户明确要求不包含赞赏图时，才设置 `reward_assets: false`，并记录 `reward_assets_omission_reason`。常规专辑默认启用；单张表情不要求专辑素材。
